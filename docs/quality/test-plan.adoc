== Test levels

[cols="2,3,3",options="header"]
|===
| Level | What it verifies | Command and file
| Domain unit tests | Rotation and layouts, fairness, completions, settlements and takeovers, history and calendar, expenses and money, mascot mood, flat validation, Tricount link | `npm test`, `src/domain/*.test.ts`
| Components and hooks | Forms, screens and stores with Testing Library, including i18n, navigation and the back button | `npm test`, `src/components/*.test.tsx`, `src/hooks/*.test.*`, `src/i18n/*.test.ts`
| Architecture | Layers do not depend on each other and there are no cycles | `npm test`, `src/architecture.test.ts` (ArchUnitTS)
| Firestore rules | Who can read and write what, using the emulator | `npm run test:rules`, `firebase/firestore/rules.test.ts`
| Data layer | Firestore operations with the real rules | `npm run test:rules`, `src/firebase/*.emulator.test.ts`
| Full application | Create a home, mark and reopen against the emulators | `npm run test:rules`, `src/App.emulator.test.tsx`
| End to end | Real browser: Android (Chromium) and iPhone (WebKit), on the emulators (create with the simulated Google popup, join, release, delete, offline) and against the deployed environment | `npm run e2e`, `e2e/emulator/*.spec.ts`, `e2e/deployed/*.spec.ts`
|===

Thresholds: logic layers with a minimum of 90% of lines, functions and statements and 85% of branches (`npm run test:coverage`).

== Manual tests before every release
Those that cannot be fully automated:. Install the app on a real iPhone (Safari) and a real Android, and open the home offline.. Receive the install prompt on iPhone and check that it disappears when dismissed.. Check by eye the look in light and dark mode.
