== Test levels

[cols="2,3,3",options="header"]
|===
| Level | What it verifies | Command and file
| Domain unit tests | Rotation, fairness, completions, flat validation, Tricount link | `npm test`, `src/domain/*.test.ts`
| Components | Forms and screens with Testing Library | `npm test`, `src/components/*.test.tsx`
| Architecture | Layers do not depend on each other and there are no cycles | `npm test`, `src/architecture.test.ts` (ArchUnitTS)
| Firestore rules | Who can read and write what, using the emulator | `npm run test:rules`, `firebase/firestore/rules.test.ts`
| Data layer | Firestore operations with the real rules | `npm run test:rules`, `src/firebase/*.emulator.test.ts`
| Full application | Create a flat, mark and reopen against the emulators | `npm run test:rules`, `src/App.emulator.test.tsx`
| End to end | Real browser: Android (Chromium) and iPhone (WebKit) against the deployed environment | `npm run e2e`, `e2e/*.spec.ts`
|===

Thresholds: logic layers with a minimum of 90% of lines, functions and statements and 85% of branches (`npm run test:coverage`).

== Manual tests before every release
Those that cannot be fully automated:

. Install the app on a real iPhone (Safari) and a real Android, and open the flat offline.
. Receive the install prompt on iPhone and check that it disappears when dismissed.
. Check by eye the look in light and dark mode.
