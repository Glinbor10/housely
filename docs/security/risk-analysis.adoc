= Security: risk analysis and data protection
:toc:
:lang: en

== Data processed
* First names of the flatmates (personal data).
* Anonymous Firebase Auth identifier per device.
* Cleaning dates linked to each member.
No special-category data, location or payment data is processed. The Tricount link is a URL; the expenses are not accessed.

== Principles applied
* *Minimization:* only name and activity; no email or phone.
* *Access control:* Firestore rules limited to the flat's members.
* *Secrets:* service account keys live only in GitHub Secrets.
* *Separate environments:* test data goes to `housely-ci`.
* *Transport:* all traffic goes over HTTPS (Firebase Hosting and SDK).

== Data protection
Use among flatmates falls under personal or household activity, which Article 2(2)(c) of the GDPR excludes from its scope. As long as the app is used only this way, there is no formal obligation; if it were opened to third parties or commercialized, this would have to be reviewed (privacy policy, legal basis and user rights). This is not legal advice.

== Abuse protection (public app)
The app is meant for flatmates but is public, so it is protected in layers:

. *Rules*: creating a flat requires an identity linked to Google; joining requires a valid invite code; there are caps per identity (3 flats) and per flat (20 people, 1040 weeks). An anonymous identity alone can neither read nor write any flat.
. *App Check*: Firebase only answers requests that carry a token proving they come from this app in a real browser. Without it, a script that only knows the public web config (it ships in the page) is rejected. The reCAPTCHA v3 site key is injected per environment as `VITE_APPCHECK_SITE_KEY`; with no key (local work, tests, emulators) App Check is off.
. *Quota watching*: the Spark plan cannot be billed, so the worst case is losing a day of service when the free daily quota runs out. Usage is reviewed in the Firebase console; if the app grows, moving to Blaze with a spending cap is the decision to take (it would also enable scheduled backups and budget alerts).

=== Enabling it in an environment
. Create a reCAPTCHA v3 site key for the domains of the environment and register it in Firebase console > App Check > Apps > Web.
. Add the repository variable `VITE_APPCHECK_SITE_KEY` to the GitHub environment (`ci`, `production`) and deploy.
. Watch the App Check metrics for Authentication and Firestore until the share of verified requests is nearly 100%.
. Only then press *Enforce* for both services. Enforcing earlier would lock out installed copies of the app that have not updated yet.
