== Niveles de prueba

[cols="2,3,3",options="header"]
|===
| Nivel | Qué verifica | Comando y fichero
| Unitarias del dominio | Rotación, equidad, completados, validación de pisos, enlace de Tricount | `npm test`, `src/domain/*.test.ts`
| Componentes | Formularios y pantallas con Testing Library | `npm test`, `src/components/*.test.tsx`
| Arquitectura | Las capas no dependen unas de otras ni hay ciclos | `npm test`, `src/architecture.test.ts` (ArchUnitTS)
| Reglas de Firestore | Quién puede leer y escribir qué, con el emulador | `npm run test:rules`, `firebase/firestore/rules.test.ts`
| Capa de datos | Operaciones sobre Firestore con las reglas reales | `npm run test:rules`, `src/firebase/*.emulator.test.ts`
| Aplicación completa | Crear piso, marcar y reabrir contra los emuladores | `npm run test:rules`, `src/App.emulator.test.tsx`
| Extremo a extremo | Navegador real: Android (Chromium) e iPhone (WebKit) contra el entorno desplegado | `npm run e2e`, `e2e/*.spec.ts`
|===

Umbrales: cobertura de las capas de lógica con mínimo del 90 % de líneas, funciones y sentencias y del 85 % de ramas (`npm run test:coverage`).

== Pruebas manuales antes de cada release
Las que no se pueden automatizar del todo:

. Instalar la aplicación en un iPhone real (Safari) y en un Android real, y abrir el piso sin conexión.
. Recibir el aviso de instalación en iPhone y comprobar que desaparece al descartarlo.
. Comprobar a ojo el aspecto en modo claro y oscuro.
